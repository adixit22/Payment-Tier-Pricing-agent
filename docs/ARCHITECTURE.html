Two-Track Pricing Agent

Architecture. Inputs on the left, deterministic tools in the middle, grounded answer on the right.

1. USER

GTM, finance, or leadership team member asks a question in natural language. Examples: "Quote Elite + Creator Pro", "Project revenue for 100 Pro customers", "Which tier fits a company with 30 hires/yr?"

↓

2. CLAUDE (LLM)

Reads the system prompt + user question. Decides which tool to call and with what arguments. Never invents prices; orchestrates only. Runs on claude-sonnet-4-6.

↓ tool_use ↓
quote_packageLine-item quote, auto-applies 20% bundle discount when both tracks are selected.
project_revenueMulti-cohort revenue projection with per-cohort ARPA and blended ARPA.
recommend_tierRules-based tier fit based on annual hires, campaigns, ATS needs.
lookup_tier_detailFull feature record for a single tier. Sales-enablement depth.
list_all_bundlesCanonical All-Access bundle catalog with list, discounted, and savings.
↓ reads from ↓

3. PRICING DATA (source of truth)

Structured Python dictionaries encoding the two-track pricing model: Hiring tiers (Starter / Pro / Elite / Enterprise), Creator tiers (Creator Starter / Creator Pro / Enterprise), and the 20% All-Access bundle rule.

↑ tool_result ↑

4. CLAUDE (synthesis turn)

Receives tool output as structured JSON. Formats a readable answer with the numbers grounded in the tool's math. May call another tool if needed (agent loop supports up to 6 turns).

↓

5. ANSWER

Natural-language response back to the user: a quote summary, a projection, a tier recommendation with rationale, or a feature comparison.

Example flow: "Quote the flagship bundle for a mid-market prospect"

  1. User prompt goes to Claude.
  2. Claude identifies intent → calls quote_package(hiring_tier="elite", creator_tier="creator_pro").
  3. Tool reads pricing_data.py, computes subtotal $19,998, applies 20% discount = $4,000, returns $15,998.
  4. Claude gets the JSON back and writes: "Flagship All-Access: $15,998/yr (saves $4,000 vs list)."

Why this architecture?

RELIABILITY The model never generates a price. Math happens in deterministic Python, so every answer is auditable.
EXTENSIBLE Adding a new tool (e.g. churn model, ARR forecast) is a new function + a new schema entry.
TESTABLE Tools are pure functions with unit tests. CI can catch pricing drift.
FAST Most questions resolve in one tool call and one synthesis turn.
